# 5H4D3R5 shader and demo plugin (2026-09-19)

Status: `DONE`. Durable behavior is normative in [`Specs/Plugins/Plugins_API.md`](../../Plugins/Plugins_API.md)
(the `Plugins/5H4D3R5` section, raised extents, template and contract-test requirements) and
[`Specs/Core/Core_Settings.md`](../../Core/Core_Settings.md) (the 5H4D3R5 settings object). The user page is
[`docs/plugins/5h4d3r5.md`](../../../docs/plugins/5h4d3r5.md).

## Goal

A bundled widget that shows a full-screen shader from the settings, a random one, or a slideshow of a fixed
catalog, starting with twelve Shadertoy works, with the authors credited and their licenses carried into the
repository:

XlsBDf, 3sySRK, tsScRK, Ms2SD1, tdG3Rd, tsXBzS, tlVGDt, ltffzl, 3l23Rh, MdfBRX, WsccDH, 7csXD4.

The same day a thirteenth entry joined the catalog: `cosmic-orb`, a RedXe demo shader supplied as HLSL (not a
Shadertoy work), which is why the catalog's Shadertoy id became optional and its license column carries the
repository terms. The plugin was then renamed from "Shadertoy" to 5H4D3R5 (`builtin.5h4d3r5`, `5H4D3R5.dll`,
`Plugins/5H4D3R5/`, code prefix `Shaders`) because it hosts any shader or demo, not only Shadertoy ports; the
word Shadertoy now appears only where it names a work's origin or license.

## Decisions

- Build-time HLSL ports, not a GLSL runtime. RedXe forbids runtime shader compilation and `d3dcompiler_47.dll`, so
  each shader became a Shader Model 5.0 pixel shader compiled by MSBuild. A small compatibility header keeps the
  Shadertoy uniform names, the bottom-left coordinate convention, and the GLSL spellings HLSL lacks, so a port reads
  like its source and the author's header survives verbatim.
- One shared settings header (`Plugins/5H4D3R5/ShadersSettings.h`) for the catalog, the modes, the ranges, and
  the defaults, compiled into the host parser and the DLL, so the list of names in the schema, the validators, and
  the plugin cannot drift. The `shader` value is a short lowercase name (`seascape`, `protean-clouds`, ...) rather
  than the opaque Shadertoy id, which the catalog keeps for attribution; the user page shows a live thumbnail of
  every entry.
- `renderScalePercent` (default 50) renders into an offscreen texture and upscales, because Seascape, Protean clouds,
  The Drive Home, and the synthwave terrain ray-march every pixel and the XENEON canvas is 2560×720.
- Multi-pass sources (Fluid solver, Flammes 3) run their "Buffer A" as a ping-pong feedback pass at the render
  resolution in `R32G32B32A32_FLOAT`, once per presented frame; half floats would swallow the fluid's dissipation.
- Heartfelt samples a Shadertoy stock photograph. RedXe does not redistribute it and generates a procedural
  night-street background with a mip chain once per device instead; the port and the docs say so.
- Time is per cycle: a slide (or an hourly cycle for single/random) restarts `iTime` and `iFrame` at zero and fades
  through the dashboard background, which keeps the 32-bit `iTime` precise over long uptimes and gives the slideshow
  a transition for free.
- A click or tap on a slideshow skips to the next entry. Rather than mutating a cycle counter, the tap adds to a
  clock offset so the timeline stays a pure function of one clock; the offset targets the fade before the next
  boundary so the same fade-out/fade-in plays. The Up is consumed (no double-click raise on a slideshow tile, per the
  interactive contract); single and random tiles leave clicks to the host.
- Licensing: four authors state CC BY-NC-SA 3.0; the other eight state nothing, which Shadertoy's terms place under
  the same default license. `Plugins/5H4D3R5/LICENSES.md` records every port, author, source URL, and license;
  the user page repeats the table and states the non-commercial, share-alike terms.

## Validation

- `.\test.ps1 -Configuration Debug -Platform x64 -Rebuild` and `-Configuration Release`: `SettingsTests` (schema,
  templates, merge, rejections), `PluginContractTests` (contract, rejections, every port on WARP at 50 % and 100 %,
  slideshow order and fade, shared resources, device loss, allocation-free `Render`), `HostPluginTests` (both
  templates map and construct with the new page).
- Screenshots for the user page come from `RedXe.exe --screenshot` on a Debug build (a primary-monitor dock bar
  with a 1:4:1 page and `--widget 1`; `docs/screenshots/README.md` has the recipe), one per catalog entry.
